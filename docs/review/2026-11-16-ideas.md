# Ideas, ranked (review of 2026-11-16)

Every idea from this review in one list, best first. "Best" means how much it would improve the assistant's results or the owner's experience, for the work it takes, with things that other ideas build on ranked higher.

Tags:
- **[plan]**: accepted and already in `docs/plans/`. Details in the [wakeups review](2026-11-16-wakeups-and-providers.md) or the [hub review](2026-11-16-hub.md).
- **[new]**: added in the fourth pass, when this list was sorted.
- No tag: a proposal from an earlier pass.

Bugs and code improvements aren't here; they're in the [bug list](2026-11-16-bugs-and-code.md).

## 1–10

1. **A model proxy that holds the provider credentials.** [plan] The agent's CLIs call a proxy inside the stack. Metering becomes exact on every provider, a budget is enforced by refusing the next request, and the sandbox holds no login or key. Needs a real-account test first.

2. **A wrap-up check control runs itself.** When a session ends cleanly, control looks at facts it already has: was `NOW.md` changed in this run, is there a journal section, is any wakeup planned, are claims still open, are there uncommitted files in a project repo. If something is missing, the session continues once with the list. No model judges anything. Continuity between runs is what the design rests on, and today it depends on the agent remembering.

3. **Delegates across providers.** [plan] The main session hands sub-tasks (bulk reading, test loops, boilerplate) to a child session on a cheaper provider, charged to that provider's pool. The strong model plans and checks.

4. **Cheap subagents in the seed, today.** [new] Claude Code already lets a session hand work to subagents that run on a smaller model: a definition file per agent in `.claude/agents/`. Seed the workspace with two or three (a reader on the small model, a test-runner, a summariser) and add four lines to the core prompt on when to use them. It's the delegate idea for a single provider with no harness work at all, and their usage is already in the session's stream. Check that the session's totals include them.

5. **Wakeups say what they need, and control picks the provider.** [plan] `light`, `standard` or `strong`. Control routes at start time: the allowance that expires soonest first, then flat-rate before pay-per-use. A closed gate reroutes instead of skipping.

6. **Flexible wakeups: a window and a piece of work, not a time.** [new] Most planned wakeups don't need 02:00 exactly; they need "tonight, about 20 points, the importer tests". Let the agent say that (earliest, latest, needs the GPU free or not) and let control place it: after a job ends, away from the owner's 5-hour window, on the pool that's about to expire, merged with a neighbour to save a wakeup's overhead. When an item finishes under budget, the run takes the next queued item instead of ending. Timed wakeups stay for real events. The agent decides what's worth doing; control does the packing, which it's better at.

7. **Wake on events and check scripts, not guesses.** [plan] A wakeup starts when a registered job ends or the owner answers a question. A timed one can run the agent's own script first, with no model, and skip itself.

8. **Warn before a run is cut off, and say how the last one ended.** [plan] Notices at 75% and 90% of the budget and ten minutes before the deadline. A "since your last run" section in the brief, written by control from its own records.

9. **A real-account smoke suite.** Five scripted scenarios on a real login before each release, transcripts kept. Almost every "unverified" note in the development plan is this gap.

10. **Backups, now.** `./l0w backup` to an encrypted archive (the database, the vault key, `/workspace`, `/work` minus opted-out folders), a restore tested in CI, a nightly schedule, and "last backup" on Settings → System. Required before joining a hub.

## 11–25

11. **A second domain for agent-made content, opened with visit tokens.** [plan] Nothing the agent made is served from the control UI's hostname. A friend's browser opens your service at its own hostname with a one-minute token from their instance.

12. **Sign and encrypt the message, not the connection; the key is the identity.** [plan] Messages verify whatever path they took, the operator can't read them, and a member can move hubs and keep friends.

13. **Scheduled messages that cost nothing.** [new] "Remind me on Friday to renew the domain" shouldn't need a wakeup on Friday. `assistant remind --at TIME "text" [--thread N]` stores a message that control posts and pushes at that time with no model. Same for the owner: a reminder on a task. Reminders are the most basic thing a personal assistant does, and today each one would cost a run.

14. **A loop and stall detector, with the reviewer called by signals.** Control sees for free the same tool call repeating, a long stretch with no note, output sizes exploding, or half the budget gone with no claim touched. It sends a notice through the hook, and only then calls the reviewer. Cheaper than watching every ten minutes.

15. **Claims with an estimate and a check.** `assistant claim N "plan" --estimate 40 --check tools/importer-tests.sh`. Above a threshold the owner sets, the claim waits for an OK. At `claim done`, control runs the check with no model and shows pass or fail. Estimates are compared with actuals afterwards.

16. **One schedule for the instance, one allowance pool per provider.** [plan] Hours, wakeups per day and gaps describe the owner's day. The level becomes one choice. Routing and delegates build on it.

17. **Use the CLIs' own hooks for more than delivery.** [new] Only the after-tool hook is used. Two more would help:
    - *Before the context is compacted*: long wakeups get compacted and lose detail. A hook at that moment tells the agent to checkpoint `NOW.md` first, and after compaction the session is given the run's facts again (budget left, open claims, the deadline).
    - *When the session is about to stop*: the wrap-up check, the "you still have budget" nudge and gate mode can hold the session open from inside, instead of letting the process exit and resuming it, which re-reads the conversation.

    Check both hooks against the pinned CLI versions, and what opencode's plugin offers in their place.

18. **An onboarding interview.** A built-in first run asks the owner a dozen questions through cards (what you want help with, what to do with spare budget, how you like to be written to, what's off limits) and writes the answers into its memory and a starter backlog.

19. **Outcome feedback, and what the points bought.** The owner marks finished work good, not what I wanted, or wasted effort. Spend is shown per project and thread next to what came out. The weekly review reads both. A "results to review" list in the Inbox, next to the asks, is where the marking happens.

20. **Briefs built for the wakeup's purpose.** A planned wakeup gets its project's doc, the thread's rolling summary and the last journal section about it, with the generic lists cut down. Reply now gets a summary plus the last few messages instead of thirty verbatim.

21. **Reply automatically.** [new] Messages are queued until the owner presses Reply now. Add a switch per thread, and "for the next hour", that starts a reply run whenever the owner writes, within the reply budget. When you're in a conversation with it, pressing a button after every message is the wrong default.

22. **A run continues on another provider when one hits its limit.** [plan] The files, `NOW.md`, notes and claims carry it across.

23. **Autonomy per project.** [new] One setting on a project: just do it / show me the plan first / ask before each change. It's enforced by the claim threshold (item 15) and stated in the brief. The home-automation project and the research project shouldn't have the same rules, and today the only way to say so is prose in a thread.

24. **An on-demand harness guide in place of a long core prompt.** The core prompt keeps the rules that must always hold. The how-to moves into `assistant help <topic>`.

25. **Read big things with the cheap model.** [new] `assistant digest FILE|URL --question "…"` makes one call to the `light` group and returns a short answer, without starting a session. A 300-page log, a long thread or a documentation site gets read for a fraction of what it costs to put it through the main model's context. Billed to the run.

## 26–45

26. **Deadlines and priority on what the owner asks for.** "By Friday", "urgent". The brief sorts by it and `assistant budget` warns when the plan can't reach a deadline.

27. **Pause everything.** One switch on Home and in the CLI: stop the run, hold all wakeups, routines and Reply now. With a duration ("for 3 hours"), it's also the "I need my Claude limit back now" button.

28. **A tunnel service that's always in the stack.** [plan] Joining and leaving a hub happen in the UI.

29. **A fake hub for development.** [plan] The hub's core with no Cloudflare, and a compose file with two instances.

30. **Recorded real runs as test fixtures, and a bot that tries new CLI versions.** [new] Capture a real session's event stream once per scenario (redacted) and replay it through the adapters in tests. The fake runtime is hand-written from what the CLIs emitted in November; the fixtures show when a new version changed the format. A weekly CI job bumps the pinned Claude Code and opencode versions, runs the fixtures and the smoke suite, and opens a pull request. The plan's first listed risk is the headless interface changing.

31. **A job queue, not only a registry.** `assistant job queue "label" -- command` runs jobs one after another when the GPU is free, survives runs and restarts, and can wake the agent when it empties.

32. **Approval rules.** "Allow this and others like it" from a card. Also where "Allow for project" should land.

33. **A budget request the agent can file.** "The importer can be done this week with 80 more points" as a card that sets a Boost.

34. **Inbound webhooks.** [new] A secret URL per hook. A request to it lands as a file in `_inbox/hooks/<name>/` and can start a small wakeup, within the schedule and a daily cap. GitHub, Home Assistant, a cron job on another machine and a phone shortcut all speak this, and it needs no hub. The payload is untrusted data.

35. **A recovery key and a daily self-check.** [plan] For a lost or stolen instance key, and to notice a hub serving the wrong one.

36. **A database copy before every migration, and a rollback for updates.** [new] `./l0w update` should copy the SQLite file before control applies migrations, keep the previous image digests, and offer `./l0w rollback`. If the health check fails after an update, roll back on its own. Friends will update unattended.

37. **The week's incidents, handed to the weekly review.** [new] Control lists what went wrong, from its own records: runs cut off at their budget, wakeups missed or skipped, checks that failed, estimates off by more than double, asks that went stale, wrap-up checks that had to resume. The review turns each into a line in the manual or a changed habit. The agent can't learn from what it doesn't remember happened.

38. **Model try-outs.** Replay a past brief on a different model in a scratch copy of the workspace; compare cost, time and result.

39. **Watchers.** The runner runs the agent's check script on a timer with no model; a change starts a small wakeup. The owner sees the list and can switch any off.

40. **Search the assistant's memory.** Full-text over `/workspace`, rebuilt after each run's commit, for the agent, the chat and the owner.

41. **An audit page.** Every approval, denial, secret read, settings change, new session and connected app in one list, with the standing approvals and a revoke button on each.

42. **A note on each planned wakeup.** [new] `assistant wake at … --note FILE`: a note to self that opens that wakeup's brief. The reason field is 300 characters, and `notify` goes to whichever run comes next. "Start with step 3; the fixture is in `/work/x/tmp`; don't rerun the download" belongs to one wakeup.

43. **Hold a run open only when the owner is around.** Skip the five-minute hold when no session has been active for an hour or it's quiet hours; hold longer when the owner is in the app.

44. **Scoped device tokens.** Read-only, and "everything except approvals, secrets and settings", for coding agents using the `l0w` CLI.

45. **A digest for the owner.** One notification a day or week, opt-in: what got done, what's waiting, what's planned, what it cost. Written by the utility role, which is stored and unused.

## 46–65

46. **`assistant doctor`.** A control-shipped check for the agent's memory: `NOW.md` older than the last run, the manual over its limit, notes missing from the index, no journal section, big files in `/workspace`.

47. **Projects on wakeups and runs.** `--project P` on a wakeup; a run's project from its claims and thread. Exact spend per project, a cap on a project's share, the project on the Calendar.

48. **Per-project instructions.** Included only when the run is on that project.

49. **A notification when a claimed task is done.**

50. **A usage forecast.** [new] "At this pace the weekly meter reaches your reserve on Thursday" on the budget page and in `assistant budget`, from the last days' slope, split into yours and the assistant's. People notice limits when they hit them; this is the day before.

51. **Levels described in hours of work.** "Steady: about 6 hours of standard a week; last week you used 4."

52. **Tell me when my server is down.** [new] A dead server can't notify anyone. Control pings a URL the owner sets (any uptime-check service) every few minutes, and the scheduler's own tick feeds it, so a stuck scheduler counts as down. With a hub, the hub notices a member that stopped checking in and tells its owner.

53. **Disk and health reporting.** Volume sizes, database size, a warning before a disk fills.

54. **Friend codes and delivery tokens.** [plan] Against friend-request spam and unsolicited delivery.

55. **"What it knows about me."** The assistant's notes about the owner, each with "that's wrong" and "forget this".

56. **Reviewer value on the page.** Turns, interjections, how often the agent changed course afterwards, points spent.

57. **Plan statistics for the agent.** Overhead per wakeup (points before the first real work and after the last), share of budget used, how often it was cut off or found nothing to do. Shown in `assistant budget`; planned wakeups smaller than about twice the overhead are refused.

58. **A project history.** [new] A dated list on each project, built from closed claims, shelf changes and decisions: what was done, when, with links to the run and the result. The data exists; nothing assembles it. After three months it's the only way to answer "what has it actually done on this?"

59. **The owner's calendar.** A read-only feed for allowed hours and real events.

60. **`./l0w doctor`.** [new] One command for a friend whose install misbehaves: Docker and Compose versions, disk, ports, the clock, DNS from inside each container, the isolation self-test, the login state, the last errors, all in a paste-ready report with secrets removed.

61. **A chat-app bridge.** [new] A Telegram bot first: what you send it lands in General (or a thread you pick), and the assistant's messages and notifications come back. Approvals and secrets stay in the app, with a link. People already have a chat app open; fewer have this one open. As an extension, since it adds an outside service.

62. **Snapshots of the agent's volumes** before a run and before an update. "Undo last night."

63. **Share to the assistant.** The installed app as a share target on the phone, and a bookmarklet on the desktop.

64. **See exactly what it was told.** [new] On any run: the system prompt and the brief as sent, and which version of each prompt file. Runs record the prompts' hashes, so behaviour before and after a prompt edit can be told apart.

65. **Export and import a setup.** [new] Levels, the schedule, groups, routines, notification choices and approval rules as one file, with no secrets. A friend starts from your tuned setup instead of the defaults, and it doubles as a settings backup.

## 66–90

66. **Snooze and expiry for asks.** "Remind me tomorrow"; say when a question's default takes effect and show assumed ones as such.

67. **A harness-requests list.** The specs the assistant writes for harness changes, with "copy for a coding agent" and "open as a GitHub issue".

68. **Signed images and pinned digests.** Verify before recreating; show the running digest and both CLI versions.

69. **Retired models.** Catch "no such model", fall back to the group's next entry, tell the owner once.

70. **Borrow a friend's GPU** (with a hub). A published job queue with a quota.

71. **Backup buddies** (with a hub). Encrypted backups on a friend's instance or the hub's storage.

72. **A routine library.** Optional built-in routines: verify old notes, check dependencies, test the backup, clean the cache.

73. **Spend alerts for pay-per-use pools.** [new] A push at amounts the owner sets, and when a day's spend is well above the usual. Real money should never be a surprise.

74. **An urgent flag the agent can use sparingly.** Pushes during quiet hours, a few a week.

75. **Inline previews for linked files** in threads.

76. **A workspace size guard.** When a run adds more than a few MB to `/workspace`, the next brief says so.

77. **A trash for the owner's deletes.** 30 days.

78. **Per-project secrets by default** when one is requested from a project's thread.

79. **Egress allowlist as a setting**, with a "learn" mode that proposes rules from a week of traffic.

80. **A run bundle for bug reports.** A run's brief, timeline, events and settings, redacted, as a zip.

81. **Voice notes in.**

82. **Favours between friends** (with a hub). [new] Your assistant asks a friend's assistant to do a piece of work; their owner approves; both sides keep a ledger of points spent for each other. It gives the spend breaker a friendlier face: the balance is visible, and a friend who only takes shows up as one.

83. **Recipe sharing** (with a hub). [new] Routines, check scripts, subagent definitions and skills as small signed packages on the board. Installing one is the owner's action, with the contents shown.

84. **Email as a notification channel.** [new] The owner's own SMTP server for the digest and for notifications, next to push and ntfy.

85. **A capability sheet.** [new] `assistant can` prints what this run may use right now: egress rules, secret names, integrations and their tool policies, the GPU, limits. The agent spends tokens discovering these one failure at a time.

86. **Secret expiry reminders.** [new] An optional "expires on" for a secret, with a task card a week before, and "last used" shown, so dead ones get removed.

87. **Travel.** When the browser's time zone differs from the saved one for a day, ask whether to move the schedule.

88. **The wakeup plan as a calendar feed.** [new] A private ICS link, so the plan shows in the owner's own calendar.

89. **Sync per-browser preferences** (time format, theme).

90. **Read-only guests.** A share link to one project's shelf or one thread. A public surface, so it wants its own review.
